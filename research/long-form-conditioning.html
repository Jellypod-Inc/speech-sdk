  • The SDK integrates 16 TTS backends + the Speechbase gateway — not the four in the brief. Derived from src/providers/: OpenAI, ElevenLabs, Deepgram (Aura), Google (Gemini TTS), Cartesia, Fish Audio, FAL (f5-tts/kokoro/orpheus), Gradium, Hume, Inworld, MiniMax, Mistral (Voxtral), Murf, Resemble, Smallest AI, xAI (Grok).
  • Core defect (confirmed in code): nothing is carried across chunk or turn boundaries. Both long-form paths fire independent, parallel requests and concatenate audio. No previous_text, no context_id, no request-ID chaining, no audio prefix, no persistent streaming session. Voice identity is held only by re-passing the same voice string.
  • Only three providers expose cross-request prosodic conditioning the SDK could thread on its existing batch paths: ElevenLabs (request stitching), Hume (context.generation_id, one step back), and Cartesia/Fish via WebSocket sessions the SDK does not implement.
  • Biggest no-new-protocol win: prefer a single request up to each model's real max input. Stop chunking models whose true window is far larger than declared — MiniMax: SDK says 3 000 chars, real cap is 10 000.
  • Latent correctness bug: Murf, Resemble and Mistral have hard per-request caps but declare no maxInputChars, so long inputs are sent in one request and rejected by the provider — they never reach the stitch path.
Provider-capable ≠ reachable through the SDK. Cartesia (WebSocket continuations) and Inworld TTS-2 (prior-audio conditioning) do condition across outputs — but only via WebSocket/Realtime sessions. The SDK uses single-shot REST/stream(), so those surfaces are not wired today. The matrix tracks both the provider capability and whether it is reachable on the SDK path.

1b · How long text is sent today

Single-speaker — generateChunkedSpeech (src/generate-speech.ts:353)

  • splitTextByMaxChars splits at the best boundary (paragraph › line › sentence › whitespace, penalty-ranked). Boundary selection is good.
  • Chunks generated with mapWithConcurrency — in parallel (default 6).
  • Each chunk is an independent provider.generate(); only the voice string + providerOptions are shared.
  • Decoded to PCM16 and concatenated at gapMs: 0 — no crossfade, no level match, no conditioning.

Multi-speaker — runStitch (src/conversation/stitch.ts:74)

  • Per-turn independent generateSpeech() calls, also parallel, concatenated with gapMs (default 300) + RMS level-normalization. No cross-turn conditioning.
  • A native single-call dialogue path exists for generateDialogue providers (ElevenLabs v3, Gemini, Fish s2-pro, Hume) — but any per-turn providerOptions force the lossy independent-request fallback (dispatch.ts:64).
What's carried across boundaries today: nothing. Grepping every provider for context_id, previous_text, continue, seed, session, wss://, prefix, continuation yields no state-threading. stream() is one request per call — there is no persistent WS/session abstraction anywhere in the SDK.
Gateway invariant. On the gateway path the SDK must be byte-equivalent to curl against api.speechbase.ai. Any conditioning we add must be implemented client-side for direct factories and expressible on the gateway wire so the server can mirror it — never a client-only behavior on the gateway path.

OpenAI / Mistral / Murf / Resemble / Smallest / Gradium / FALNone — no cross-request conditioning existsn/aStuck with independent-chunk concat; document as best-effort

(b) Multi-speaker scripted dialogue continuity

Best mechanism is a single native dialogue call so the model conditions all speakers together: ElevenLabs eleven_v3 Text-to-Dialogue (≤2 000 chars, ≤10 voices), Gemini multi-speaker (max 2), Fish s2-pro speaker tags (SDK caps 4), Hume utterances[] (SDK caps 4). The SDK already routes to these — but any per-turn providerOptions force the lossy independent-request stitch path (dispatch.ts:64), throwing away cross-speaker conditioning. Everything else can only be stitched.

(c) Conditioning on a live user's incoming audio (S2S)

No provider offers this on the plain TTS endpoints the SDK calls. It lives in separate products: Gemini Live, OpenAI Realtime, Inworld Realtime, xAI Voice agent, ElevenLabs Speech-to-Speech, and batch voice-changers (Cartesia, Murf, Resemble). The SDK has no S2S/live surface at all — this is a green-field module, not a tweak to generateSpeech.

Step 4.2 — Specific SDK code changes

All changes honor the gateway invariant: implement client-side for direct factories, and add the same fields to the gateway wire so the server can mirror them.

Change 1 — Long-form strategy descriptor on SpeechProvider

type LongFormStrategy =
  | { mode: "single-pass" }      // send one request up to maxInputChars
  | { mode: "request-stitch" }   // previous_text/next_text + previous_request_ids
  | { mode: "context-id" }       // chain on a returned generation/context id
  | { mode: "ws-continuation" }  // persistent WS session (future)
  | { mode: "independent" };     // current behavior; seams expected

interface SpeechProvider {
  longFormStrategy?(modelId: string): LongFormStrategy;
}

Change 2 — Thread conditioning through generate() and capture prior-output ids

generate(options: {
  conditioning?: {
    previousText?: string; nextText?: string;
    previousRequestIds?: string[];   // ElevenLabs
    contextGenerationId?: string;    // Hume context.generation_id
  };
}): Promise<{ requestId?: string; generationId?: string; /* ...existing */ }>;
  • ElevenLabs: map to previous_text/next_text/previous_request_ids; read the request-id response header. Return single-pass for eleven_v3.
  • Hume: map contextGenerationId → { context: { generation_id } }; return the new id. Same-version only.

Change 3 — Make generateChunkedSpeech strategy-aware (the central fix)

  • request-stitch/context-id: run chunks serially and thread state forward (prev text + prev request-id / generation-id). Fixes seams for ElevenLabs & Hume.
  • single-pass: don't chunk if text fits the (corrected) cap.
  • independent/unset: keep current parallel concat as fallback; add a short equal-power crossfade in concatPcmToWav to soften energy jumps.

Change 4 — Correct maxInputChars + add missing caps

  • MiniMax 3000 → 10000. Murf add 3000. Resemble add 2000. Mistral add conservative cap. Gradium 20000 is unverified — lower or mark provisional.

Change 5 — (Larger) Persistent streaming-session abstraction

Add an openSession()-style API (distinct from one-shot stream()) holding a connection + context_id + push()/flush()/finish(), surfacing max_buffer_delay_ms. Unlocks Cartesia continuations, Fish tts-live, Deepgram/Murf/MiniMax/Gradium/Smallest WS, and is the right home for capability (c). Its own milestone — Changes 1–4 deliver most of the win without it.

Change 6 — Preserve native dialogue conditioning under per-turn options

In dispatch.ts:64, where a provider can express per-utterance options in its native dialogue call (Hume utterances[], Fish per-speaker), pass them through natively instead of falling back to stitch.

Step 4.3 — Recommended default + per-provider fallback

Default policy (single speaker)

  1. If text fits the model's real maxInputChars, send one request — best coherence. Big-window models (Gemini ~32k tok, flash_v2_5 40k, xAI 15k, MiniMax 10k, multilingual_v2 10k) cover most long agent turns this way.
  2. Else chunk + apply the best conditioning: ElevenLabs (non-v3) → request stitching (serial); Hume → generation_id chaining; Cartesia/Fish → WS continuation once Change 5 lands.
  3. Else (no primitive) → independent-chunk concat + crossfade, voice id held constant. Seams expected.

Routing tiers

TierProvidersLong-form route
Best for long narrationElevenLabs (flash_v2_5 / multilingual_v2), Hume Octave, Gemini TTS, MiniMaxbig single pass and/or native conditioning

Cannot do long-form conditioning at all (independent requests only): OpenAI, FAL (all), Resemble, Mistral, Murf, Smallest, Gradium, MiniMax (beyond its 10k single pass), Deepgram, Inworld (REST path). For these, long-form coherence = hold the voice id constant and accept seams.

Multi-speaker default: prefer the native dialogue call (ElevenLabs v3, Gemini, Fish, Hume); everything else → stitch with gapMs. Live audio (c): out of scope for generateSpeech; build a separate realtime module if needed.

Step 4.4 — Open questions needing empirical testing

  1. Boundary artifacts: measure pitch drift / energy jump at gapMs:0 joins per provider, with/without crossfade; quantify how much ElevenLabs stitching & Hume chaining actually remove.
  2. eleven_v3 char cap: Models page says 5 000, help center says 3 000 — confirm against a live 422.
  3. Request-id availability: verify the request-id header on our tier; confirm zero-retention disables stitching.
  4. Cartesia context expiry (1s): measure buffering latency cost; tune max_buffer_delay_ms (0–5000, def 3000).
  5. Fish condition_on_previous_chunks: does it reduce seams across separate WS messages, or only within one generation?
  6. Serial vs parallel cost: serial chunking (needed for stitching) raises wall-clock latency — quantify the trade.
  7. Unverified caps: empirically find true max for Gradium, Smallest, MiniMax (confirm 10k), kokoro, orpheus, Mistral.
  8. WS cross-message state (Deepgram, Murf, MiniMax, Gradium, Smallest): docs silent — test before claiming continuity.
  9. Gateway parity: every conditioning field added client-side must be mirrored by the Speechbase server.
